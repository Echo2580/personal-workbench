# 个人工作台

> 它不是某个问题的解决方案，而是一系列功能的聚合体——每个人的工作台，都不尽相同。

我们想搭建一个个人工作台，用来解决日常学习和工作中的一些问题：你缺什么，就往里加什么。

最开始，我们只是想把散落的项目放到一起，方便随时打开。现在，工作台也能接住群里的通知、今天的待办、长期的学习计划，还有临时冒出来的一个想法。

## 现在的痛点

学习中，你做完了一个又一个项目。可这些项目，事后你还在持续使用吗？有没有常回头看看？

我现在的项目就散落在各个文件夹里，平时接触不到，存在感自然低——只能吃灰。偶尔想回头看看，还得翻文件夹、回忆怎么跑，于是更不想动了。

事情也差不多。老师在群里发了通知，截了图，却忘了把截止时间记下来；想复习一门课，计划写了不少，今天具体做什么还是没安排；突然有个想法，随手记在某个地方，之后又找不到了。

所以，我们继续往这个工作台里加功能：项目能打开，通知能变成待办，计划能落到每天，想法也有地方放。

## 第一个功能：项目集中 + 启动器

工作台的第一个功能，就是冲着这个痛点来的：把散落的项目集中到一处，让你闲来无事时，能随手回顾任何一个项目。

- 自动扫描你指定的目录，散落的项目汇成一张清单
- 每个项目一条“启动配方”：跑命令、开 IDE、开文件夹，点一下就走
- 配方大多能自动识别（认得出 `main.py`、`package.json` 这些特征），认不出的改一行就行
- 项目可以改名、搜索筛选、移除和恢复；启动后的受管理进程，也能在工作台里停止

这个功能现在已经可以日常使用了，多配方、独立控制台、进程树跟踪与停止都已实现，也在真实项目上验证过启动与管理。详细能力和各项目的核验情况见[验收记录](docs/acceptance.md)。

## 第二个功能：截图转待办

群通知里往往同时有时间、要求和提交方式。每次都靠自己重新抄一遍，容易漏；只留一张截图，又不方便安排和提醒。

现在可以把截图或文字交给工作台，让 AI 先整理出待办草稿，再由你核对后保存。

**截图 / 文字 → AI 提取 → 核对编辑 → 保存待办 → 回看原文原图。**

- 截止时间、任务要求等内容可以在核对时修改，不合适的草稿可以删掉
- 保存后进入同一份待办清单，之后也能回看任务来自哪段文字、哪张图片
- 没有截图也能直接手动新建，不必每件事都经过 AI

这个功能已经作为原生模块并入工作台，导入、核对和待办管理都在同一个界面里完成。

## 第三个功能：把待办安排到每天

任务记下来了，还得知道今天做什么、做到了哪一步。我们给待办加了月历、筛选和长期任务，让零散的事情能排进日程。

- 用月历按天查看任务，也能在列表里搜索、筛选、编辑和标记完成
- 把长期目标拆成计划，或按周期生成习惯任务，查看完成进度
- 不知道怎么拆时，可以让 AI 给出规划草稿，预览后再决定是否保存
- 为任务设置提醒，在工作台页面打开期间提示到点事项

提醒需要保持工作台页面打开；打开页面前已经到点的提醒不会补发。

## 每天从首页开始

不想一进来就翻好几个页面，首页先把常用的东西放在眼前：

- **今日待办**：今天到期和逾期未完成的任务，直接查看和勾选；未安排日期的任务另有入口去清单处理
- **天气与世界快讯**：记住你选的城市，查看天气和来自公开 RSS 的新闻；新闻标题可以打开原文
- **常用入口**：打开工作台模块、最近使用的项目，也能添加自己的常用链接
- **接下来**：根据真实待办展示今天和未来一周的安排
- **随手记**：多行记录想法（Enter 保存、Shift+Enter 换行），长内容可打开详情查看全文、编辑、复制或转成待办

想找之前的内容，按 **Ctrl + K** 就能搜索项目、待办、长期任务和笔记；点击笔记结果可以直接定位。

目前整站使用深墨绿、炭灰和浅黄绿的界面。浏览器窗口放大，首页会利用更多空间；窗口缩小，卡片会调整排列，内容可以继续滚动。调整窗口时，尚未保存的输入也会保留。

## 如何安装和启动

需要 Windows 和 Python 3.12 或更高版本（安装时勾选 Python Launcher）。首次安装依赖需要联网；日常界面不依赖 CDN 或 Node 构建工具。

1. 把仓库克隆到自己选的目录：

   ```powershell
   git clone https://github.com/Echo2580/personal-workbench.git
   ```

2. 双击仓库根目录的 `install.cmd`，脚本只在本仓库内创建 `.venv` 并按锁文件安装依赖。

3. 安装完成后双击 `start.cmd`，服务就绪后会自动打开工作台首页。以后日常使用都只点 `start.cmd`，不用手工起服务。

4. 首次使用在“设置 → 扫描目录”里添加你放项目的目录，工作台就会自动扫描。

也可以在 PowerShell 里完成安装：

```powershell
Set-Location -LiteralPath '你的仓库路径'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
.\start.cmd
```

`Bypass` 只对这一个进程生效，不修改全局执行策略。

### 使用 AI 功能前

截图 / 文字提取和 AI 规划需要你自己的 DeepSeek API Key。在 Windows 的用户环境变量中添加 `DEEPSEEK_API_KEY`，值填写自己的密钥。当前默认使用 `deepseek-flash`，世界快讯的 AI 筛选也使用这份配置。

项目管理、手动待办、随手记和数据备份等功能不需要模型密钥。新闻的 AI 筛选失败时，会退回标题列表，仍可打开原文。

使用 AI 提取和规划时，相应输入会发送到模型服务。密钥只在本机配置，不要放进仓库或备份文件。

## 数据放在哪里

个人配置和运行数据保存在**项目目录内**的 `data\`（即 `<项目根>\data\`，如 `wb\data`、`wb-stable\data`），不进仓库；服务只绑定 `127.0.0.1`，在 17843–17852 中选可用端口。需要临时指定其它目录时，可用 `--data-dir` 参数或 `WORKBENCH_DATA_DIR` 环境变量。

想留一份备份，可以到“设置 → 数据备份与恢复”导出；需要恢复时，也从这里导入。恢复前会自动保存一份当前数据。导出的备份包含任务、长期目标、笔记、偏好、项目配置等，不包含项目代码、运行日志和 AI 密钥。

更多安装和数据目录细节见[交接说明](docs/交接/2026-10-16-项目交接说明.md)。

## 稳定版与开发版

日常使用用 `start.cmd`；调试改动时用 `start-dev.cmd`。两个副本的数据各自跟着项目目录走：日常稳定版在 `wb-stable\data`，开发版在 `wb\data`，互不影响。

本地开发时，我们把代码也分成两个目录：

- `wb`（主仓库 `main`）：**开发版**，功能与修复先在这里完成并通过回归
- `wb-stable`（独立 worktree）：**稳定版**，日常运行的是它（端口 17843），开发过程中不直接改动
- 每次把开发版迁移到稳定版时，都会给对应提交打 Git tag，当前稳定版为 **[v0.5.2](docs/releases/v0.5.2.md)**

发布和回滚流程见 [docs/release.md](docs/release.md)。
