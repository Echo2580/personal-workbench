## 6. 持久化、接口与运行安全

| 本地文件 | 内容 |
|---|---|
| `settings.toml` | 扫描根目录、默认解释器、扫描选项 |
| `projects.toml` | manual_projects、overrides、removed_projects、project_names |
| `cache/projects.json` | 可重建扫描缓存，不是人工配置事实来源 |
| `history/projects.json` | 动作和运行历史，最多500条 |
| `history/approvals.json` | 配方确认指纹 |
| `runtime/instance.json` | 实例快速定位缓存，含令牌，不公开、不手工盲删 |
| `logs/service.log` | 滚动日志 |

配置保存使用内容revision和If-Match、临时文件替换及`.bak`备份。人工配置不应被扫描覆盖。目录规范化后的完整SHA-256是项目身份，名称不是身份；PID本身也不是进程管理授权。

项目API前缀为 `/api/v1`，重要入口：

- GET `/projects`；POST `/projects/scan`；POST `/projects/manual`。
- GET/PUT `/projects/{id}/recipes`；DELETE `/projects/{id}/override`。
- POST `/projects/{id}/recipe-approval`、`/actions`；GET `/projects/runs`；POST `/projects/runs/{id}/stop`。
- DELETE `/projects/{id}`移除；GET `/projects/removed`；POST `/projects/{id}/restore`。
- PATCH `/projects/{id}/name`保存`{name}`；DELETE同一路径恢复默认。修改与恢复都要求If-Match。
- GET/PUT `/settings/projects`。
- GET `/system/about`、`/system/shutdown-preview`；POST `/system/shutdown`。

bootstrap可取得会话，变更请求需要会话令牌和正确同源Origin。不要在文档、终端输出或提交中暴露令牌。执行必须引用已保存的ID/指纹；不要将交接、配置保存或静态检查理解为批准执行真实业务。

Job流程为挂起创建 → 加入KILL_ON_JOB_CLOSE Job → 恢复；入口退出但子进程仍在时保留运行状态。停止是终止整个受管理树，不保证第三方优雅清理。服务异常退出后旧运行标为interrupted，不按旧PID接管。

测试/开发服务必须使用独立WORKBENCH_DATA_DIR和空闲端口，禁止在真实项目运行时对生产使用reload。
